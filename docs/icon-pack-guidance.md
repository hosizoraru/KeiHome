# Icon-pack guidance and actions

Long icon-pack pages share page-level guidance instead of repeating the same instructions in each pack card. The card shows a short summary; MIUIX ExpandMore / ExpandLess icons and content animation expose the remaining notes. The icon pack's apply and update actions never depend on this expansion state.

Settings > Icon packs and actions > Compact icon-pack guidance is stored in MMKV and defaults to off. Enabling it moves applicable informational notes into a directly accessible topbar Info action, displayed in a MIUIX WindowDialog with a bounded, scrollable body and a dismiss button. It applies to APK / MTZ / ZIP lists, ColorOS details, and the long Perfect / Apple configuration, mapping and search pages. Short source/credits pages and important short-page guidance remain visible. Errors, eligibility failures, progress, cooldowns, pending generation changes and confirmations are not hidden by this setting.

Imported pack cards emphasize the primary system-theme action. Visible action labels are concise (Apply / Update / Import / View), while accessibility descriptions retain the full action and pack name. Action buttons have explicit horizontal and vertical spacing and keep a 48dp minimum touch height; wrapping remains available at large font sizes. Existing ordinary APK / MTZ / ZIP imports also expose **Update imported icons** beside it; this regenerates from the current source, whereas opening an existing theme does not. Generated Perfect / Apple packs retain their own generation workflow. Opening a previously imported theme is a compact native navigation row, without another branded instruction card or duplicate link on the generated Perfect card.

Author/designer pills appear only when the source declares a usable value; equal author/designer names are shown once. Installed APK descriptions reuse the existing version/update/configuration-aware cache. Imported MTZ metadata continues to use its declared description. Optional APK metadata reads explicit CandyBar author string aliases, or the bounded Arcticons contributor declaration tied to its dashboard title. Generic app/publisher labels, package names and dashboard-framework credits are not treated as icon authors. Missing or malformed optional attribution does not block import; cancellation is propagated.

Acceptance evidence is stored under `.artifacts/research/pack-guidance-20261109/`. This change is app UI/metadata work: native payload is preserved, and normal API 102 deployment must separately verify Launcher, SystemUI and system_server process identities. It does not require applying a new icon theme.
