# 深浅色壁纸搭配

在「桌面 → 桌面外观 → 深浅色壁纸搭配」中，可以为两个系统外观模式
分别选择一套「系统个性化」搭配。每一项显示系统保存的锁屏和桌面预览。
选择「保持当前壁纸搭配」后，进入该模式时继续使用当时的搭配。
设置搜索也能打开这个面板。搭配调度使用系统的深浅色状态，与 KeiHome
自身的配色和壁纸调暗设置分别生效。

## HyperOS 应用链路

主题管理器 11.5.6.0 的 `TemplateApplyController` 调用 `com.miui.aod`
的 `miui.keyguard.editor.templatefileprovider`。KeiHome 的系统框架
作用域通过同一提供方读取 `callGetHistoryTemplates`，并调用
`callApplyHistoryTemplate`，传递当次读取到的历史条目和整套应用参数。
锁屏样式、景深以及桌面壁纸继续由 HyperOS 应用。面板只接收搭配标识
和按需读取的缩略图。搭配文件与历史记录由系统管理。

系统应用一套历史搭配时，会把原搭配归档进历史记录，并可能复用原有
条目 ID。保存时使用壁纸内容与配置计算的标识。匹配时规范化搬迁路径、
应用时间和裁切矩阵的微小浮点漂移。动态景深搭配从当前目录或当次历史
目录识别图像和视频，避免依赖配置中可能指向旧目录的资源路径。搭配在
系统中删除或被修改后，失去匹配的选择会提示重新选择。

系统端监听外观配置与远程偏好变化，在后台串行应用。读取预览时缓存
文件摘要，面板在回到前台或系统搭配配置变动时刷新。手动刷新期间
保留已有缩略图。API 102 热重载通过 `RestartableMonitor` 等待旧监听
和任务线程退出。

目前适配 HyperOS 4 主用户下，由该系统提供方返回且能解析壁纸
资源的搭配。系统提供方、搭配格式和素材路径都属于 OEM 实现。

## 实机验证

Xiaomi 17 Pro `pandora`，`OS4.0.8.0.XBLCNXM`，桌面 `801030308`，
AOD 编辑器 `DEV-2458.3.0.1-10231109`。b0747 覆盖安装后在原
`system_server` 进程完成 API 102 热重载。实机验证了刷新、两张预览、
分模式保存，以及 KeiHome 退到后台后的两轮深浅切换。每次都核对了桌面
和锁屏的壁纸文件、时钟效果、动态景深标记与静态人物资源。
b0746 补充验证了两种搭配的实际锁屏画面，以及「保持当前壁纸搭配」
在切换模式时保留当时的壁纸。验证后恢复初始深色模式和原搭配，
并清除两档测试绑定。

b0747 通过了 Release 构建、Release lint 和搭配标识的三项单元测试。
