# Launcher 9261 兼容性

HyperOS Phone AVD `emulator-5580` 已原位更新到 `com.miui.home` 的
`RELEASE-8.01.02.9261-261013-11142146-R`（`801029261`）。
已安装 APK 的 SHA-256 与用户提供的文件一致。

## 输入与解析

- APK SHA-256 为 `9e503bc3733e856cc8821e9f2770a467b5fa6c49aef3fc52c82e3cea5127decd`。
  签名证书 SHA-256 与 9259 同为 `c9009d01ebf9f5d0302bc71b2fe9aa9a47a432bba17308a3111b75d7b2149025`。
- DexSQL 确认 9259 和 9261 都没有 DEX。`libapp.so`、
  `libresources_frb.so` 与 `libnative_widget_sdk.so` 的字节发生变化，
  `libapp_launcher.so` 相同。检查 Flutter 入口时，使用实际映射的
  `libapp.so` 验证调用关系，使用 APK 的调试数据生成离线对照。
- Monet 取色解析允许背景闭包从对象池加载浮点常量时使用不同槽位。
  图像恢复在经过验证的方法体内查找类型检查、cast、clone 与 RenderImage
  分配调用，并交叉验证 CID、对象布局和分配入口。闭包的成对加载可以直接
  编码对象池的低位偏移。
- Dock 通过分支目标关系校验 scroll 慢路径。Dock 与材质刷新单独解析共用的
  响应式状态与刷新入口。Monet 资源选择、图像恢复和 Dock 新出现的指令结构
  由离线生成器纳入契约，运行时依照结构查找并拒绝歧义。
- 9261 的 `Marquee` 由 `AospMarqueeText` 创建。新调用约定包含完成回调、
  间距与速度，旧桥接因此拒绝启用自定义标签。系统标签仍正常显示。
- 标签解析器现在检查原生组件的初始化字段、分配器标记、状态类型检查与
  内部滚动组件的构造调用。调用目标和类 ID 从当前 `libapp.so` 解析。
  确认结构后，桥接把文本和样式交给原生组件，由它创建滚动状态、渐隐和
  完成回调。旧版继续走直接构造路径。无法唯一确认结构时回退到系统
  标签，共用刷新仍可独立解析。

## 验证

- 离线 Monet 选择、取色、图像恢复与异步支持门通过 12 个桌面版本。
  Dock 结构和拒绝用例通过相同的 12 个版本。9261 的 Dock 解析结果另与
  APK 内调试数据比对。
- JVM 测试 2085 项通过、8 项条件跳过。Release `112000691` 构建及
  `lintRelease` 通过。设备验收使用 Debug 构建。
- AVD 安装 KeiHome Debug `112000688`。观察到 10 次成功的 API 102 Java
  热重载，失败和未知结果均为 0。总目标数无法由日志确定。单独验证了
  新原生库加载，Monet、Dock 和材质均报告初始化成功。
- 实际打开桌面、文件夹、最近任务及系统设置并返回。应用已导入的
  Arcticons Material You 后验证浅色和深色模式下两组配色的原生回执和
  Dock 图标像素。测试使用系统配置确认模式切换，再等待桌面原生回执，
  避免测试进程处于后台时读到旧的资源配置。
- 原主题、配色、深色模式、自定义图标配置及 70 条布局记录验收后均与
  基线一致。`system_server` 和 SystemUI 进程连续运行。

## 应用名称复验

- 桌面 7722 至 9261 共 12 份 ELF 通过解析回归，包含布局或类标记
  不匹配及调用目标错误的拒绝用例。源码桥接与构建产物各通过
  8166 个 ARM64 用例，覆盖对象移动及分配空间不足时的回退。
- Phone AVD 原位安装 Debug `112000692` 后，9261 报告原生滚动组件
  已就绪。「跟随系统」「长名称轮播」「两行显示」均收到桌面确认。
  对照同一页的滚动帧和两行截图，长名称轮播正常，短名称稳定，切页
  返回后仍可滚动。原设置恢复为「两行显示」。
- 加载新原生库时桌面进程重新初始化一次，`system_server` 和 SystemUI
  持续运行。观察到 9 次 Java 热重载成功。系统在更新期间回收了
  `com.android.settings:provider`，对应的 1 次热重载记录为失败。
  主题、配色、深色模式、自定义图标和 70 条布局记录与基线一致。

## 桌面链路复扫

- 搜索胶囊属于独立解析的材质入口。原来的能力位随 Dock 基础材质
  一起上报，可能在搜索胶囊缺失时仍确认搜索栏设置。现在由成功安装
  的搜索入口决定独立能力。仅有基础材质时，客户端在同一次连接中
  发送 Dock 设置并保留已保存的搜索栏选择。测试覆盖完整、部分、
  缺失三种能力，以及拒绝错误命令时保留现有设置和租约。
- Phone AVD 上的 Debug `112000693` 确认了独立搜索栏设置。对照
  「搜索栏跟随浅色 Dock」与「搜索栏强制深色」的桌面裁图，搜索栏
  随设置变化，Dock 保持浅色。同一桌面进程确认了独立材质与跟随
  设置。Dock 模式、共享刷新和图标高光解析通过离线检查。图标
  高光尚缺已挂载图标的视觉复验。
- 从应用入口重新生成并应用 Arcticons Material You。原生回执和
  当前主题文件哈希一致。蓝、粉两套配色在浅色和深色模式下均通过
  桌面像素校验，关闭 Monet 后换色保持图标像素一致。旧验收资源
  已不存在，因此复测使用本次生成的资源。验收后通过主题壁纸重新
  应用并校验了原主题哈希。
- 状态栏工具的旧快照曾显示深色图标。返回桌面后重新读取，
  当前窗口请求已是浅色图标，截图也确认深色壁纸上的白色前景。
  手动刷新返回成功并恢复原深色模式。
- MAML 元数据释放在框架 SDK 上就绪。将 9261 的桌面自带
  `libnative_widget_sdk.so` 补入反例，验证它继续被判作另一种对象
  布局，避免将框架释放逻辑套在桌面组件上。
- 这次安装观察到 9 次 Java 热重载成功，随后桌面重新初始化以加载
  新原生库。SystemUI、`system_server` 持续运行。主题、配色、
  自定义图标、Dock 与搜索栏选项及 70 条桌面布局记录已对照恢复。
