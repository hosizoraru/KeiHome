# 原生代码升级后的重启建议

## 发布时如何启用

在 `ReleaseNotesCatalog` 对需要提醒的发布条目设置
`recommendSystemRestart = true`。普通 Java / UI 更新保持默认 `false`。
按语义版本前缀记录，不按 Git 后缀或构建号记录。

1.11.0 是首次启用此机制的版本：本版包含 9258 动态结构解析的原生库更新，
API 102 Java 热重载不能替换其他进程已经加载的 `.so`。
建议用户更新后手动重启系统；确认按钮不执行重启。

## 展示和持久化

- 升级更新日志先显示。用户读完或返回后，导航回到模块主页，
  等原生导航转场完成才显示 OS4 Glass 确认弹窗。
- 1.10.0 未公开发布；1.9.0 升级至 1.11.0 时，默认同时展开
  1.11.0 与 1.10.0。通过版本目录的 `expandOnUpgrade` 配置，
  不改变手动查看历史时默认仅展开当前版本的行为。
- 确认前至少等待 5 秒，使用单调时钟，并在点击回调内再次检查时间。
  返回和点击弹窗外部都不视为确认；快速重复点击只交付一次。
- 弹窗退出动画完成后，单独持久化已确认版本。阅读更新日志不等于确认重启建议。
  重建 Activity 或未确认时进程退出不会丢失待提醒记录；重新展示时重新等待 5 秒。
- 同一版本前缀的不同构建不重复提醒。后续另一个声明了重启建议的版本可以再次提醒。
  跨过多个相关版本时，只提醒最新的适用版本；普通更新保留尚未确认的提醒。
- 全新安装继续使用首次启用向导，必须启用模块、授权后重启；不额外堆叠升级提醒。
- 此机制记录“已知晓”，不记录“已实际重启”，也不据此改变运行状态诊断。
  清除 App 数据会丢失确认记录。

`ReleaseNotesPolicy` 负责纯状态转换，`ReleaseNotesPreferences` 使用原有独立本地存储，
`UpgradeRestartReminder` 负责计时和弹窗。后续版本无需复制计时或迁移逻辑。

## 参考边界

核对了本地 `MiuiBackGestureHook` 的 `README.md`、`AGENTS.md`、
`tools/Dev-Deploy.ps1`：它也将普通 Java 代码替换与 native/spawner 生命周期分开，
原生更新的开发部署操作会先准确验证 `hyos_spawner`。它的系统镜像重定向模式还特别要求
模块更新或移除后重启。不同项目的注入方式不同，不能直接照搬进程终止逻辑。

KeiHome 这里只提供清楚的用户建议，不在用户点击确认时终止宿主或自动重启设备。
开发验收脚本的 `--reload-native` 仍是独立的显式操作。
